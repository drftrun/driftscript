# Code of conduct

## The short version

**Be someone people can work with.** Disagree about the code as much as you like; the code is what
we are here for. Do not make it about the person holding the opinion.

## What that means in practice

- **Argue with the claim, not the author.** "This breaks when the target provides no registry" is a
  review. "This is careless" is not.
- **Assume the other person read the thing and reached a different conclusion.** Usually they did.
- **Take a "no" once.** A maintainer refusing a feature is not an invitation to re-open the thread
  from a new angle. If the reason given is wrong, say why it is wrong.
- **No harassment, no abuse, no sexualised language, no personal or political attacks, no publishing
  anyone's private information.** This is the ordinary list and it is not negotiable.

## Scope

Issues, pull requests, discussions, and anywhere someone is representing this project.

## Enforcement

Report privately through GitHub: open a
[private report](https://github.com/drftrun/driftscript/security/advisories/new) on this repository,
which is the private channel it has. That form is labelled for security, and a conduct report sent
through it reaches the same person and stays just as private.

Reports stay private. A maintainer will edit, hide or delete anything that breaks the above, and
will say that they did and why. Someone who keeps doing it is blocked. **A single serious incident is enough** — there is
no strike count, because a rule that requires three warnings is a rule that tolerates two.

This project is small enough that enforcement is one person exercising judgement rather than a
process. That is stated plainly so nobody expects an appeals board that does not exist.
